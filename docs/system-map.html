Where the alpha actually flows

This is a strategy catalog with a provenance-aware simulation layer. Every number knows whether it came from the frozen paper, a user assumption, a real Yahoo price, or a cosmetic literal. The architecture is seven layers; each layer depends only on the layer below. Hover a flow to trace a number's lineage.

2Catalog → Signalscategory → rule

3Signals → Enginesrule → engine
The signal rule is passed to the simulation or historical engine.

4User Input → Enginessliders → μ, σ
User drags return/vol sliders. This drives synthetic backtests.
USER INPUT — synthetic alpha enters here
5External Data → EnginesYahoo → overlays
Optional network fetch through a user-supplied CORS proxy. The only live-data path.
LIVE (OPTIONAL) — real prices, naive rules
6Engines → Resultsequity[] → object
Engines output provenance-tagged objects: dates, equity, returns, drawdowns, metrics, assumptions.
LABELED — every number knows its source
7Results → Analyticsmetrics → derived
Sharpe, drawdown, win rate are derived from the result series. Cosmetic metrics are injected here too.
DERIVED — computed or labeled
8Analytics → Presentationnumbers → UI
React pages render results with Recharts and KaTeX. Pages are read-only consumers.
PRESENTATION — dressed as a result
9Cosmetic → Analyticsliterals → Analytics
VaR / ES / trades / correlation matrix are hardcoded or random. Not computed from data.
COSMETIC — the leak
10Config → StatusSettings → status.ts
API keys, endpoints, and Swagger URLs are stored locally. No live connection or trading.
CONFIG ONLY — no execution
